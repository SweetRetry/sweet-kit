# UI Layout and Loading 规则

## 核心指导原则

优先利用负空间、表面色调差与动态反馈建立视觉秩序；禁止使用高对比度的 1px 闭合边框作为内容分隔手段。

## Spacing

页面和组件布局中的 `padding`、`margin`、`gap` 与 `space` 必须遵循 8px 网格。

- 常规间距使用 `8 × n`：8px、16px、24px、32px、40px、48px、64px 等。
- 4px 是唯一允许的半步间距，仅用于图标与文字、标签与辅助信息等紧密关联元素。
- 页面留白、区块间距和容器内边距不使用 4px。
- 使用 Tailwind 标准 spacing utility，不使用 6px、10px、12px、20px 等偏离网格的值或 arbitrary value。

## 规则

1. **负空间定义分组**：根据内容的从属关系规划间距，使组内间距明显小于组间距；通过留白、对齐、网格和容器宽度表达区块边界。
2. **排版建立层级**：使用标题层级、字号、字重和文字颜色组织阅读顺序，不依赖容器轮廓补救层级不清。
3. **表面高度表达层次**：布局先确定表面的承载、抬升或内凹关系，再按 [UI Color and Surface](../ui-color-and-surface/README.md#表面高度) 映射柔和的明度差，避免高对比度描边。
4. **动态反馈表达可交互性**：交互区域通过 hover、pressed、focus 等状态的色调、阴影或形变反馈其边界和状态，不使用静态闭合边框代替交互反馈。
5. **分隔线不是默认分区方式**：页面、卡片、列表项和表单区块不使用高对比度 `border`、`divide-*`、`<Separator />` 或同类线条进行常规分区。

## 适用边界

本规则约束内容分区，不限制承载明确语义或状态的边界，例如键盘焦点、选中状态、校验错误，以及图表或数据网格自身需要表达的关系。

## 加载状态

页面或主要内容区首次加载时使用与最终内容结构一致的 Skeleton；Loader 只反馈局部操作的进行状态。禁止用居中或全屏旋转 Loader 替代页面骨架。

### Skeleton

- 路由级 `loading.tsx`、页面首次加载和主要内容区首次加载使用 Skeleton。
- Skeleton 应复现最终页面的主要布局、尺寸和内容层级，加载完成后不应产生明显布局跳动。
- Skeleton 只占位尚未获得的内容，不清除或覆盖已经可用的页面内容。

### Loader

- Loader 只用于按钮提交、局部刷新、分页加载和其他范围明确的操作。
- Loader 放在触发操作的控件或正在更新的局部区域内，不阻塞无关内容与操作。
- 局部刷新和增量加载时保留已有内容，不切换为页面级 Loader。

## 验收

- 移除内容区块的闭合边框和分隔线后，分组关系与阅读顺序仍然清晰。
- 相邻内容的间距体现接近性原则：组内紧凑，组间疏朗。
- 所有布局间距均为 8px 的整数倍；4px 仅出现在紧密关联元素内部。
- 不依赖 hover 时，静态内容层级仍然成立；进入交互状态后，操作边界和当前状态能够被识别。
- 边框或线条一旦出现，能够说明其承载的具体语义，而不是仅用于装饰或弥补布局问题。
- 页面级加载状态能够看出最终页面的主要结构，不出现仅有一个旋转图标的空白页。
- Loader 的位置能够明确指出正在等待的操作或局部区域。
- 已加载内容在局部操作期间保持可见，且页面布局不会因加载状态切换发生明显跳动。
