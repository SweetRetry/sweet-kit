# Rules

`rules/` 保存当前有效的专项工程约束，由 [AGENTS.md](../AGENTS.md) 与 [DESIGN.md](../DESIGN.md) 按任务路由。

## 编写原则

- 写清如何选择、适用边界和必要例外；保留影响判断的参数、对照表与短例子。
- 每条都应能据此做出一个决定；需要解释机制时写成适用条件（判据），不描述成因。
- 同一约束只说一次，不在原则、反模式与验收清单中重复。
- 实现取值查代码与配置，依赖 API 查文档与类型；不复制完整能力清单、教程或 ADR 的决策背景。
- 精简表达不等于改变约束；修改原则、阈值或适用范围时，应明确说明。
- 新规则必须有入口引用；单篇用 Markdown 文件，需要配套脚本时才建目录。

## 验证边界

- 可执行的不变量优先用类型与测试守护；涉及视觉或业务判断的内容由评审验证。
- className 约束由 `.oxlintrc.json` 的 `@shadcn/lint` 检查；其他源码扫描仅用于边界明确、误报率低的规则。
- 静态门禁统一运行 `pnpm rules:check`。修改受检查约束时，同步核对对应配置、脚本或测试。
