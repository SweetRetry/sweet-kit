# Surface Elevation 规则

## 核心原则

**越靠近用户，表面越亮。**

布局关系先决定表面的感知高度，色彩明度再把高度变为可见线索。表面越靠近用户，它相对承载表面的合成明度越高；越接近画布基底，明度越低。

这是视觉高度模型，不是 CSS `z-index` 的数值映射。`z-index` 只在高度语义确定后实现重叠顺序。

## 高度模型

| 高度 | 布局语义 | 常见对象 |
| --- | --- | --- |
| **Elevation 0：基底** | 最远的连续画布 | 应用背景、编辑画布 |
| **Elevation 1：结构面** | 建立持久分区的基础表面 | 侧边栏、主面板 |
| **Elevation 2：抬升面** | 从承载表面上分离的内容或控件 | 抬升卡片、列表项、工具控件 |
| **Elevation 3：浮层** | 临时覆盖当前内容的顶层表面 | 弹窗、下拉菜单、Popover、Tooltip |

在同一局部抬升链中，合成后的感知明度遵循：

```text
Elevation ↑ = Lightness ↑
```

主题具有可用明度空间时，完整的四层链满足 `L(E0) < L(E1) < L(E2) < L(E3)`。明度差保持微弱但可识别，表面彩度保持低且稳定；色相不承担高度表达。

## 判断顺序

1. **先定布局关系**：根据承载、嵌套、重叠、脱离文档流与临时覆盖关系判定高度，不按组件名称固定分级。卡片可以与父表面齐平，也可以被抬升。
2. **再定明度关系**：抬升子表面比承载表面亮。不相交的区域只保持自己局部链的顺序，不为达到全局绝对顺序而提亮。
3. **最后补充边界**：明度不足以稳定分离表面时，使用主题化的微光边界、阴影或其他深度线索。边界表达高度，不作为常规内容分区线。

## 内凹与抬升

比父表面更暗的子区域只表达内凹、内嵌或内容井，例如编辑画布、代码区或明确下沉的输入区。内凹区域使用独立语义 Token，并通过形态与交互继续表达内凹。

抬升容器保持递亮关系。嵌套本身不代表内凹，也不代表抬升；必须先由布局语义判定。

## Token 映射

Elevation 色阶是主题内部的基础 Token，组件不直接消费它。主题将 `background`、`sidebar`、`card`、`input`、`accent` 和 `popover` 等组件语义 Token 映射到当前布局所需的高度。

具体 OKLCH、Hex、alpha、状态叠加和边界取值集中定义在 `packages/ui` 的主题 Token 中。业务组件不内联固定色值，不自行生成高度色。

## 主题映射

- **暗色模式**：明度是主要高度线索。浮层使用低透明度亮色边界补充轮廓，黑色阴影只辅助脱离感。
- **亮色模式**：画布预留明度空间，使抬升面能向亮端偏移。表面已到达亮度上限时保持非递减明度，并用低对比度边界或阴影继续表达高度。
- **高对比度模式**：可访问性需求优先于明度顺序，使用系统颜色和明确边界保持层级可识别。

Hover 和 pressed 是交互状态，不自动代表新高度。交互状态使用统一叠加 Token；只有布局同时表达抬升时，才切换到更高 Elevation。

## 布局映射

### 无缝分栏

- 主画布使用 Elevation 0。
- 侧边栏与持久工具区使用 Elevation 1。
- 画布上的抬升控件使用 Elevation 2。
- 临时覆盖内容的菜单与弹窗使用 Elevation 3。

### 嵌入面板

- 窗口基底使用 Elevation 0。
- 主面板使用 Elevation 1。
- 主面板内的抬升卡片或列表项使用 Elevation 2。
- 临时浮层使用 Elevation 3。

## 验收

- 每个表面都能根据布局关系说明自己是基底、结构面、抬升面、浮层或内凹区域。
- 沿任一局部抬升链检查，表面越靠近用户，合成后的明度越高；达到主题明度上限时不得反向变暗，并有额外边界线索。
- 任何比承载表面更暗的子区域都具有明确内凹语义。
- 浮层在去掉阴影后仍能通过明度或主题边界被识别。
- 组件使用语义 Token，Elevation 取值、状态叠加与浮层边界均集中定义在 `packages/ui`。
