# 动效

动效用于解释状态、空间关系与操作反馈。使用 `motion/react` 或 Tailwind CSS 过渡，复用组件已有行为。

## 是否需要动画

- 键盘触发与超高频操作直接呈现最终状态；频率按实际使用判断，不按组件名称决定。
- 中高频操作移除或缩短动画，仅保留有助识别的反馈；偶发浮层用短过渡解释来源与层级。
- 首次引导、成功反馈可更有表现力，但操作与请求立即生效，业务状态不等待动画完成。

## 时长与缓动

以下是调参范围，不是所有组件必须采用的固定值。常规交互优先低于 300ms，退场通常不长于进场。

| 场景                   | 建议时长              |
| ---------------------- | --------------------- |
| 按压反馈               | 100–160ms             |
| Tooltip / 小型 Popover | 125–200ms             |
| Dropdown / Select      | 150–250ms             |
| Dialog / Sheet         | 200–500ms，优先较短端 |

- 进出场使用强 `ease-out`，如 `cubic-bezier(0.23, 1, 0.32, 1)`；原地形态切换用 `ease-in-out`，hover 或颜色变化用 `ease`。交互避免启动迟缓的 `ease-in`。
- Spring 用于手势、动量或中途改变目标；普通业务 UI 避免多余弹跳。配置采用 `duration + bounce` 或物理参数一套，具体签名查当前依赖。
- 缩放从接近最终尺寸开始，如 `scale(0.95)`；浮层锚点朝向触发源，居中 Dialog 使用中心锚点。
- 指针按压可用轻微缩放；键盘与减少动态效果分支保持原尺寸。同组 Tooltip 连续切换时跳过延迟与动画。

## 连续性、性能与可访问性

- 连续操作从当前视觉状态转向最新目标，不跳回起点、不排队播放过期动画；动画完成回调只做视觉收尾。
- 优先 `transform` 与 `opacity`，显式声明过渡属性，禁止 `transition-all`；复杂效果与宽高动画需检查实际开销。
- 布局变化优先检查 `layout` / `layoutId` 能力，避免逐帧更新 React 状态；动画不替代 [尺寸稳定](stability.md) 中的加载占位。
- 尊重 `prefers-reduced-motion`：移除位移、缩放和 3D 运动，可保留必要的轻微透明度或颜色反馈。Motion 与 CSS 过渡分别处理该偏好。
- Hover 只用于支持悬停的设备；减少动态效果、键盘和触屏下，焦点、操作与状态信息仍完整可用。
