# UI Design Quality 规则

本规则约束构图质量。设计由当前任务、内容关系与交互状态产生，通用组件模板不是默认答案。

## 契约

1. **一个主导关系**：每个视区或区块只保留一个首要焦点，辅助信息降低视觉重量，不与其竞争。
2. **关系先于组件**：先用顺序、比例、位置、共享刻度、连接或分组表达内容关系，再决定是否需要卡片、表格、图表。只有语义、结构和操作真正同级的对象才使用重复或等宽布局；权重不同的对象用排序、分组、占比或密度表达差异。
3. **层级先于装饰**：优先用字体、比例、对齐、密度、节奏和负空间建立层级。表面、边框、颜色、图标与动效只在增加语义或可供性时出现。分组用单层表面承载，禁止卡片套卡片。
4. **真实编码**：同级数据共享统一基准轴与比例刻度，条柱长度与面积严格线性对应真实数值。数值优先就地标注，维度过多才使用独立图例。
5. **数据宽展优先**：宽幅数据表格拥有最高水平空间优先级，横向滚动或全宽展示，不为容纳旁侧装饰而挤压列宽。
6. **文案直陈**：文案直接陈述业务数据与操作结论，不向用户叙述页面设计背景、排版理由或过往尝试。
7. **内容决定密度**：信息不足时如实保留空缺，不用面板、指标或特效填充；信息密集时先重组取舍，不通过缩小正文或压缩控件硬塞。

## 默认不用的模式

下列模式不能作为默认构图；只有当它直接表达当前任务关系、并且移除后会损害理解或操作时才使用：

| 模式 | 替代 |
| --- | --- |
| 万物皆 Card | 普通列表用留白、共享左对齐轴与 `space-y-*` 组织，不逐项套 Card + 阴影 |
| Badge 泛滥 | 普通元数据用 `text-xs text-muted-foreground`；Badge 只标强状态（`destructive`、`warning`）或核心分类 |
| 等大指标卡矩阵 | 主导指标单独放大，次要指标用紧凑对比排版；权重不同就不等大 |
| 装饰性图标块 / 插画 | 图标只在有操作识别或可供性价值时出现；空状态说明是语义信息，不算装饰填充 |
| 氛围渲染 | 无意义的渐变文字、光晕、网格纹理、斑点与彩色图标底色 |

```tsx
// ❌ 逐项 Card + Badge
<Card><Badge>{user.department}</Badge></Card>

// ✅ 留白 + 对齐轴 + 文本元数据
<div className="space-y-1">
  <p className="text-sm font-medium truncate">{user.name}</p>
  <span className="text-xs text-muted-foreground">{user.department}</span>
</div>
```

## 允许的例外

品牌沉浸、内容沉浸或实验性界面可以使用更强的装饰、色彩与动效，但必须有已确定的艺术方向。每项偏离都要支持当前内容、品牌语义或交互反馈，并保持可读性、响应式行为与可访问性；「让页面更丰富」不是理由。

## 验收

- **眯眼测试**：模糊细节后，首要焦点、分组和阅读路径仍然清楚，页面不是等权重区块的堆栈。
- **移植测试**：主要组织方式在只替换文案后不能直接用于无关业务；能够直接移植说明构图仍由模板主导。
- **同级测试**：每组重复结构中的对象具有相同语义、结构和操作；不等价对象已通过排序、分组、占比或密度体现差异。
- **移除测试**：逐项移除卡片、边框、背景、图标、颜色和动效；不损失含义或可供性的元素不得恢复。
- **响应式测试**：窄屏通过重排保持层级与操作，不依赖截断关键内容或缩小可读字号维持桌面构图。
