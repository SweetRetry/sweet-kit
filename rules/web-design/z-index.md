# 层叠

## 使用原则

- 普通布局依靠 DOM 顺序；只有需要重叠时才设置 z-index。
- 头像堆叠、焦点环、Tab 指示器等局部重叠，由父容器用 `isolate` 隔离，避免子元素参与外部排序。
- 业务层只用以下阶梯，不写任意 z-index，不超过 `z-50`；第三方组件内部层级由其自身管理。

| 层级 | 用途 |
| --- | --- |
| `-z-10` | 背景装饰 |
| `z-auto` / `z-0` | 普通内容 |
| `z-10` | 隔离容器内的局部重叠 |
| `z-20` | 局部吸顶与拖拽把手 |
| `z-30` | 固定导航 |
| `z-40` | 需要独立分层的遮罩 |
| `z-50` | 弹窗、菜单与提示等浮层 |

## 挂载与排查

- Dialog、Sheet、Popover、Dropdown、Tooltip 等全局浮层复用组件的 Portal，挂载至顶层，脱离局部裁剪。
- Accordion、Tabs 与局部吸顶条属于内容流，留在宿主容器；Sonner 使用自身管理的通知层级。
- 遮挡异常先检查 DOM 挂载顺序、祖先的 `transform`、`opacity`、`filter`、`contain` 等层叠上下文，以及 `overflow` 裁剪，不盲目增大数值。
- 同层浮层检查挂载顺序；打开弹窗后，其内部菜单、Tooltip 与通知仍应可见，不通过覆盖基础组件层级解决。
