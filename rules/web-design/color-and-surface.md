# 色彩与表面

## 色彩职责

- 每个 UI 非中性色都承担状态、注意力或分类职责；同一语义在各视图保持一致。
- 高显著色集中用于主任务或关键状态，次要操作降低视觉重量；界面框架不与图像、视频和用户创作内容争夺注意力。
- 业务组件消费 `background`、`foreground`、`primary`、`destructive` 等语义 Token。具体色值与主题映射集中在 `packages/ui`，新增语义先定义 Token。
- 关键状态同时提供文本、图形或位置线索；文字、焦点与控件在亮色、暗色和系统强制颜色下均保持可辨识的对比度。

## 6:3:1 视觉配比（60-30-10）

将视区内颜色与表面的视觉重量按「60% 基底 : 30% 结构 : 10% 焦点」分配（与[构图注意力法则](design-quality.md#631-注意力与权重法则)保持一致），避免色彩均分导致视线分散或过度刺激。

| 层次 | 视觉比重 | 职责定义 | 对应语义 Token | 越界禁令 |
| :--- | :--- | :--- | :--- | :--- |
| **60% 主基底** | ~60% | 视区画布与大底，控制画面的明暗基调与呼吸感，提供低噪稳定的视觉背景 | `background` / `foreground` | 严禁使用高饱和度或强彩度色块铺满；不得为“充实界面”滥用非必要背景装饰色 |
| **30% 辅助结构** | ~30% | 容器、面板、侧栏与次级信息承载面，构建层级结构与内容骨架 | `card`、`sidebar`、`muted`、`border` | 严禁卡片内部层叠套用多层同级表面；不得使用与基底缺乏对比或过度反差的非语义色块 |
| **10% 关键焦点** | ~10% | 主行动点（CTA）、当前激活态、焦点高亮与紧急/关键反馈 | `primary`、`accent`（交互高亮）、`destructive`（破坏操作） | 严禁同一视区出现多个等权的高彩度焦点；严禁将 `primary` 大面积用作装饰底色或次要标签 |

### 场景判据与例外

- **单向引导与转化（结算、注册、引导流程）**：严格遵循 6:3:1，确保 10% 焦点色唯一指向首要操作路径。
- **生产创作与工具（编辑器、画布、代码区）**：框架压制为 90%+ 的中性基底与低对比结构，强调色仅在光标、选择态与必要反馈微量出现（<5%），不强凑 10%。
- **信息分析与监控（仪表盘、图表、数据表格）**：颜色承担多维数据分类与业务状态（成功/警告/危险）编码职责，不受 10% 面积上限限制，但仍须以中性色为 60% 稳固基底。

## 按任务选择色彩密度

| 任务                               | 策略                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------- |
| 单向引导：结算、注册、单路径流程   | 聚焦唯一主路径；严格遵循 6:3:1 配比，背景、辅助面与焦点色明确分层         |
| 品牌表达：营销页、活动页、品牌首屏 | 品牌色可作主色大面积使用，经 Token 定义；状态语义色与文字对比度不得被削弱 |
| 信息分析：监控、图表、仪表盘       | 颜色稳定映射状态、系列或范围，配合非颜色线索，不受强调色面积限制          |
| 生产创作：设计、代码、文档编辑器   | 框架以灰阶与低彩度为主，让内容保持主导，不为凑比例添加色块                |
| 内容沉浸：影视、相册、UGC          | 框架中性，局部主题可由内容提取，经 Token 限定范围并校验对比度             |

按视区任务判断，不按产品名称分类。比例是近似参考，不能覆盖语义与可访问性；已确定的实验性艺术方向可另行调整。

## 表面高度

按「布局关系 → 组件语义 Token → 当前主题表现」选择表面。高度描述视觉关系，Token 表达组件职责，两者不是固定的一一对应。

### 高度与使用场景

| 高度                | 布局含义                 | 实际选用                                                                                               |
| ------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------ |
| Elevation 0：基底   | 连续画布或应用背景       | 页面画布使用 `background` / `foreground`                                                               |
| Elevation 1：结构面 | 侧栏、主面板等持久分区   | 侧栏使用 `sidebar` / `sidebar-foreground`；主面板按其角色选 `background` 或 `card`，不因分区就统一改色 |
| Elevation 2：抬升面 | 从承载面分离的内容或控件 | 卡片使用 `card` / `card-foreground`；工具控件沿用自身变体，以主题色差、边界或阴影表达分离              |
| Elevation 3：浮层   | 临时覆盖内容的菜单、弹窗 | Popover、Dropdown 使用 `popover` / `popover-foreground`；其他浮层遵循下文的组件映射                    |

无缝分栏通常是「画布 E0 → 侧栏 E1 → 画布上的抬升控件 E2 → 临时浮层 E3」；嵌入面板通常是「窗口基底 E0 → 主面板 E1 → 面板内抬升卡片 E2 → 临时浮层 E3」。这是布局判定示例，不要求每个页面凑齐四层，也不代表所有嵌套对象都逐层抬升。

### Token 映射与组件边界

- `background`、`sidebar`、`card`、`popover` 是表面语义；使用时配套对应的前景 Token，不凭当前颜色相似而相互替换。
- Dialog、AlertDialog、Sheet 当前使用 `background`；Tooltip 使用 `foreground` 作为背景、`background` 作为文字色。它们仍是浮层，不在调用点强行覆盖为 `popover`。
- `accent` / `accent-foreground` 表达交互高亮，不是通用的“更高一层”；`input` 用于输入控件边界及其现有暗色填充，不是内凹表面的通用 Token。
- 内凹区域需要独立的语义映射；当前没有通用内凹 Token，出现该需求时在主题中定义，不借用 `muted` 或 `input` 猜测高度。
- 色值与映射统一在 [globals.css](../../packages/ui/src/styles/globals.css) 维护。若建立基础 Elevation 色阶，由主题将语义 Token 映射到色阶，业务组件仍消费语义 Token，不直接引用高度编号或计算色值。

### 主题表现

- 暗色主题通过表面提亮、边界与阴影表达层级，不要求每层亮度都递增；亮色主题用明度差、边界或阴影分隔，不强求越高越亮。
- 同一局部链的视觉关系保持一致；表面差异微弱但可识别，不足时补充主题边界或阴影。
- 内凹由形态与交互表达，使用独立语义 Token；更暗不自动等于内凹，嵌套也不自动代表抬升。
- 系统强制颜色使用系统颜色与边界，不追踪主题明度；表面色阶也不直接对应 z-index 数值。
- 色值、状态叠加与边界统一由主题管理，组件不自行计算高度色。

Token 取值对齐 [shadcn 官方 Neutral](https://ui.shadcn.com/docs/theming#default-theme-css)：暗色 `card` 与 `popover` 比 `background` 亮但两者同值，层级由组件的边框、阴影与遮罩表达。

高度模型只用于选择语义 Token，不要求额外建立独立的 Elevation 色阶。
