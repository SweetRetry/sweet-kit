# UI Color and Surface 规则

## 色彩

色彩是信息传达系统。先确定功能、语义与任务类型，再决定色彩角色、密度和具体取值。

### 核心原则

#### 1. 色彩服务于功能与语义

每个由 UI 系统添加的非中性色都必须具有明确职责：

- **状态**：默认使用绿色表达成功或正常、红色表达危险或错误、黄色或橙色表达警告、蓝色表达信息、灰色表达中性，并保持全局一致。
- **注意力**：高显著色用于当前主任务或关键状态；次要操作使用中性或低显著样式。
- **分类**：数据系列、范围或类别只在颜色能稳定表达关系时使用多色。

新增 UI 色彩前必须能指出它承载的职责。无法指出功能或语义的色彩视为视觉噪声，使用已有中性色替代。

#### 2. UI 框架退位于内容

背景、卡片、侧边栏、输入区等 UI 载体优先使用白、灰、黑或低彩度色。层级优先通过克制的明度差、负空间和排版建立，使数据、图像、视频、文本和用户创作内容保持视觉主导。

内容已经具有高色彩密度时，UI 框架应接近无色化（Neutral/Ghost），不再用固定品牌色与内容竞争。

#### 3. 使用动态语义 Token

业务组件只消费颜色的语义角色，例如 `background`、`card`、`foreground`、`muted`、`primary`、`accent`、`destructive` 和 `ring`。具体 Hex、OKLCH 或色阶取值集中定义在 `packages/ui` 的设计 Token 中；新语义先新增对应 Token，再在组件中使用。

同一语义 Token 必须针对亮色、暗黑与系统强制颜色（`forced-colors`）分别给出可用取值。主题切换只改变映射，不改变组件的语义角色。

#### 4. 色彩密度由界面任务决定

先按当前视区支持的主任务分类，再使用对应策略。同一页面包含多类任务时，按视区分别分类，不以产品名称代替任务判断。

| 任务类型 | 色彩策略 | 常见场景 |
| --- | --- | --- |
| **单向引导型** | 高聚焦：使用 60-30-10，强调色集中引导唯一主路径 | 营销落地页、结算页、单路径流程 |
| **信息分析型** | 多色语义：用稳定色彩映射区分状态、系列与范围 | 仪表盘、监控面板、数据可视化 |
| **生产创作型** | 极致中性：UI 框架使用 90% 以上灰阶或低彩度色 | 设计、代码、文档与视频编辑器 |
| **内容沉浸型** | 动态提取：UI 载体保持中性，局部主色调由当前内容决定 | 音乐、影视、相册与 UGC 浏览 |

### 任务策略

#### 单向引导型：60-30-10

- **60% 主色（Dominant）**：画布背景或大面积中性色，承载整体环境。
- **30% 辅助色（Secondary）**：卡片、侧边栏、输入区等内容表面，建立容器层级。
- **10% 强调色（Accent）**：主 CTA、关键状态与选中态，引导第一注意力。

比例是可见面积与视觉重量的近似约束，不做像素级计数。同一视区保留一个主导强调目标，次要操作不与其使用同等视觉重量。此处的 Accent 是 60-30-10 中的视觉角色，不等同于同名的 `accent` 设计 Token；主 CTA 通常使用 `primary`，实际 Token 由元素语义决定。

#### 其他策略的额外约束

- **信息分析型**：数据色不受 10% 强调色限制；同一语义在所有图表与状态中使用同一映射，并用标签、图形、纹理或位置提供非颜色线索；状态色不兼作无关的数据分类色。
- **生产创作型**：UI 框架中性色占比可超过 90%，层级靠轻微明度差、间距与排版建立；不为凑足 30% 而增加辅助色容器；代码高亮、设计画布、文档内容与视频素材保留自身的语义色彩。
- **内容沉浸型**：封面、海报、照片或 UGC 内容决定局部主色调；动态色必须作为主题 Token 的受控输入，同时限定影响范围并验证前景对比度；固定 UI 色不与动态内容竞争。

### 横跨场景的优先级

1. **可访问性优先**：文本、焦点、状态和交互控件保持足够对比度，所有关键信息同时具有文本、图形、纹理或位置线索。
2. **高度映射优先**：表面色彩遵循 [表面高度](#表面高度)，由布局关系确定高度、由当前主题确定明度方向；`forced-colors` 优先使用系统颜色。
3. **语义优先于比例**：成功、危险、预警、信息和数据映射保持语义一致，不为满足 60-30-10 而改色。
4. **艺术方向可显式覆盖比例**：情绪表达型、品牌沉浸型或实验性界面可使用大面积高饱和色、撞色、同色系分割或强光影。偏离必须支持已确定的艺术方向，并保持内容可读与交互可识别。

### 验收

- 每个由 UI 系统添加的非中性色都能指出其状态、注意力或分类职责。
- 每个视区都能指出主任务类型，色彩密度与对应任务策略一致。
- 业务组件使用语义 Token，亮色、暗黑与 `forced-colors` 下保持同一语义。
- 页面第一注意力落在当前主任务、关键状态或内容上，UI 框架不与其竞争。
- 所有文本、交互和状态在不依赖颜色的情况下仍可理解。

## 表面高度

### 核心原则

高度是布局事实：承载、嵌套与覆盖关系决定表面远近，颜色只是让这种远近可见。因此规则约束的是**同一主题内的稳定分隔**，而不是一条跨主题的明度方向。

| 主题 | 明度承担的角色 | 典型表现 |
| --- | --- | --- |
| **暗色** | 承担高度方向 | 越靠近用户越亮：基底最暗，卡片、浮层逐层提亮 |
| **亮色** | 只承担分隔，不承担方向 | 抬升面可亮于也可暗于承载面：灰画布上的白卡片、白画布上的灰工具面板 |
| **系统强制颜色** | 让位于可访问性 | `forced-colors` 下使用系统颜色与系统边界 |

任何主题下都必须满足：

1. **局部单调**：同一局部抬升链上不使用来回翻转的明度关系。
2. **差异可感知**：明度差保持微弱但可识别；不足以分离两个表面时，补充主题化边界或阴影。
3. **内凹另有语义**：更暗不自动等于内凹，内凹由形态与交互表达，并使用独立语义 Token。

这是视觉远近模型，不是 CSS `z-index` 的数值映射；`z-index` 只在高度语义确定后实现重叠顺序。

### 高度模型

| 高度 | 布局语义 | 常见对象 |
| --- | --- | --- |
| **Elevation 0：基底** | 最远的连续画布 | 应用背景、编辑画布 |
| **Elevation 1：结构面** | 建立持久分区的基础表面 | 侧边栏、主面板 |
| **Elevation 2：抬升面** | 从承载表面上分离的内容或控件 | 抬升卡片、列表项、工具控件 |
| **Elevation 3：浮层** | 临时覆盖当前内容的顶层表面 | 弹窗、下拉菜单、Popover、Tooltip |

表面彩度保持低且稳定，色相不承担高度表达。

### 判断顺序

1. **先定布局关系**：根据承载、嵌套、重叠、脱离文档流与临时覆盖关系判定高度，不按组件名称固定分级。卡片可以与父表面齐平，也可以被抬升。
2. **再取主题色阶**：暗色按递亮链取值，亮色按分隔关系取值，取当前布局语义对应的语义 Token。不相交的区域只保持自己局部链的顺序。
3. **最后补充边界**：明度不足以稳定分离表面时，使用主题化的微光边界、阴影或其他深度线索。边界表达高度，不作为常规内容分区线。

### 内凹与抬升

内凹区域是被父表面裁剪、下沉或承接滚动的内容井，例如编辑画布、代码区或明确下沉的输入区。它与抬升面的区别来自形态与交互，不来自明度高低；内凹区域使用独立语义 Token。

嵌套本身不代表内凹，也不代表抬升；必须先由布局语义判定。

### Token 映射

Elevation 色阶是主题内部的基础 Token，组件不直接消费它。主题将 `background`、`sidebar`、`card`、`input`、`accent` 和 `popover` 等组件语义 Token 映射到当前布局所需的高度。

具体 OKLCH、Hex、alpha、状态叠加和边界取值集中定义在 `packages/ui` 的主题 Token 中。业务组件不内联固定色值，不自行生成高度色。

### 主题细节

- **暗色模式**：无可用亮度上限时，浮层用低透明度亮色边界补充轮廓，黑色阴影只辅助脱离感。
- **亮色模式**：不要营造“越高越亮”的阶梯。`background` 已接近明度上限时，`card` / `popover` 与其同亮，分离靠边界与阴影；`sidebar` 可以比画布更暗。
- **`forced-colors` 模式**：`forced-colors` 生效时使用系统颜色（`Canvas`、`CanvasText`、`ButtonBorder` 等）与系统提供的边界保持层级可识别，不追踪明度关系。

Hover 和 pressed 是交互状态，不自动代表新高度。交互状态使用统一叠加 Token；只有布局同时表达抬升时，才切换到更高 Elevation。

### 布局映射

#### 无缝分栏

- 主画布使用 Elevation 0。
- 侧边栏与持久工具区使用 Elevation 1。
- 画布上的抬升控件使用 Elevation 2。
- 临时覆盖内容的菜单与弹窗使用 Elevation 3。

#### 嵌入面板

- 窗口基底使用 Elevation 0。
- 主面板使用 Elevation 1。
- 主面板内的抬升卡片或列表项使用 Elevation 2。
- 临时浮层使用 Elevation 3。

### 验收

- 每个表面都能根据布局关系说明自己是基底、结构面、抬升面、浮层或内凹区域。
- 沿任一局部抬升链检查，明度关系不来回翻转；亮色主题中相邻表面之间始终存在可感知的分隔线索（明度差、边界或阴影）。
- 暗色主题中抬升面不得比承载面更暗；亮色主题中更暗的子区域能由形态与交互说明其内凹语义。
- 浮层在去掉阴影后仍能通过明度或主题边界被识别。
- 组件使用语义 Token，Elevation 取值、状态叠加与浮层边界均集中定义在 `packages/ui`。
