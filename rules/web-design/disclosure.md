# 收纳与渐进披露

决定一条信息或一个操作「此刻是否可见、不可见时放在哪」。判定单位是当前场景下的用户任务，不是字段或组件；同一内容在不同场景可以有不同落点。

## 1. 先判定是否直接呈现

满足任一条件即直接呈现，其余进入收纳：

- **影响此刻的决定**：缺少它会做错判断或无法完成当前操作，包括代价、不可逆后果、禁用原因与阻断状态。
- **需要同时比较**：多个值必须并排核对才能判断。
- **当前任务的高频主操作**：在该场景中反复使用，每次展开都会拖慢主流程。

「可能有用」「数据库里有这个字段」「展示得全显得完整」不构成直接呈现的理由。

## 2. 收纳去向由内容属性推出

不从组件清单里挑，先回答下面四个问题，载体是答案的组合结果：

| 问题 | 取向 |
| :--- | :--- |
| 展开后是否需要保留当前上下文？ | 需要 → 就地展开或锚定浮层；不需要且须专注完成 → 模态或独立页 |
| 内容是临时查看还是持续使用？ | 临时 → 可轻易关闭的浮层；持续 → 留在内容流中（折叠区、分段切换、侧栏） |
| 是否包含交互？ | 纯解释 → 最轻量的提示；含输入或选择 → 可聚焦、可键盘操作的载体 |
| 各部分是互斥还是并列？ | 互斥视图或模式 → 同一时间只显示一个分支；并列 → 分组后按优先级折叠次要组 |

示例（非穷举）：保留上下文 + 临时 + 含交互 → 锚定浮层（Popover、DropdownMenu）；保留上下文 + 持续 + 互斥 → 分段切换（Tabs、ToggleGroup）；不保留上下文 + 须专注 → Dialog；需要深链或分享 → 独立路由。表里推不出合适载体时，先沿用当前应用中同类场景已有的处理方式，保持一致优先于局部最优。

## 3. 场景判据

- **单向引导流程（注册、结算、发布）**：只呈现推进主线必需的内容，高级选项整体收纳并给出默认值；代价与限制仍在提交前可见。
- **专业工具与编辑器**：创作内容优先；低频工具退入菜单、面板或命令入口，高频工具保持一次点击可达。
- **数据表格与列表**：行内只保留识别与判断所需的列和主操作，次要操作进入行尾溢出菜单，完整详情进入抽屉或详情页。
- **设置页**：按任务分组，常用设置直接呈现，危险设置单独成区并直接可见，不藏进折叠区。

## 4. 越界禁令

- **不为收而收**：只有一两个次要操作时直接呈现，不单独做溢出菜单；收纳后入口比原内容更难理解时不收。
- **关键信息不进仅悬停可见的载体**：代价、不可逆后果、禁用原因、错误信息不得只放在 Tooltip 或 hover 态中；触屏上悬停不可达。
- **浮层不嵌套浮层**：模态内不再开模态；需要二级内容时改为模态内的步骤切换、就地展开或锚定浮层。
- **入口可发现**：收纳入口使用可识别的触发器（图标加可访问名称、带计数或状态的标签），不依赖用户猜测隐藏手势。
- **展开不改变决策前提**：展开后才出现的内容不得推翻用户已基于收起态做出的判断。

## 验收清单

- [ ] **逐项可答**：首屏每个可见元素都能说明用户此刻用它做什么判断或操作。
- [ ] **两态检查**：收起态与展开态都经过检查，不只看默认截图。
- [ ] **反向检查**：决定所需的信息没有被折叠、藏入悬停或二级浮层。
- [ ] **场景一致**：同一应用中同类内容的收纳方式一致。
