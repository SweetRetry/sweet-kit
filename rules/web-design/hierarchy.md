# 信息层级与收纳

决定页面信息的视觉权重、首要焦点以及次要内容的收纳去向。先理清信息关系，再选择组件承载。

## 1. 6:3:1 注意力法则与构图

视区注意力预算有限，按「60% 主体基底 : 30% 辅助结构 : 10% 关键决策」组织信息，防止视觉嘈杂或层级扁平：

| 维度 | 60% 主体与基底 | 30% 辅助与结构 | 10% 焦点与决策 | 越界禁令 |
| :--- | :--- | :--- | :--- | :--- |
| **内容与信息** | 业务主事实、默认流程主体 | 筛选条件、辅助上下文、属性说明 | 首要行动点（Primary CTA）、阻断状态 | 严禁平铺所有字段；严禁让用户在次要信息中寻找主操作 |
| **空间与留白** | 画布大底、段落宏观负空间 | 卡片内边距、组内网格间距 | 核心操作隔离留白、关键呼吸区 | 严禁无留白紧密挤塞；严禁卡片套卡片挤占内容空间 |

- **场景判据**：
  - **单向引导流程（注册/结算/向导）**：严格收敛。只保留推进主线必需信息，10% 焦点仅保留一个推进主按钮（Primary CTA）。
  - **信息看板与监控（Dashboard/统计）**：60% 面积留给图表与数据明细，30% 用于维度筛选与卡片容器，10% 聚焦核心 KPI 与报警。同级图表条柱共享统一基准轴，面积严格线性对应真实数值。
  - **专业工具与创作区（画布/编辑器/IDE）**：90%+ 空间让渡给创作内容，工具栏与面板退入 30% 辅助结构层。
- **默认构图**（偏离时，须证明该元素直接表达任务关系，且移除会损害理解或操作）：
  - **列表靠留白分组**：用留白、共享左对齐轴与 `space-y-*` 组织，Card 只给语义、结构和操作真正同级的对象。
  - **元数据保持安静**：普通元数据用 `text-xs text-muted-foreground`；Badge 仅用于强状态或核心分类。
  - **权重决定大小**：主导指标单独放大，次要指标采用紧凑对比排版。
  - **装饰只承载语义**：渐变文字、光晕、网格纹理、斑点、彩色图标底色，仅在传达状态或可供性时出现。
  - **数据宽表优先**：宽幅数据表格拥有最高水平空间优先级，横向滚动或全宽展示，不为旁侧装饰压缩列宽。
  - **文案直陈**：直接陈述业务数据与操作结论，不向用户叙述设计背景或排版理由。

## 2. 直接呈现 vs 渐进收纳

判定单位是当前场景下的用户任务。满足任一条件直接呈现，其余进入收纳：

- **直接呈现判据**：
  1. **影响此刻决定**：缺少会导致判断错误或阻断流程（代价、后果、禁用原因、报错）。
  2. **需要同时比较**：多个值必须并排核对。
  3. **当前任务高频主操作**：反复使用，折叠会严重拖慢主流程。

  只有这三条是判据；「可能有用」「数据库有这个字段」「展示全显得完整」都不是。
- **收纳载体由四个问题的答案推出**，不从组件清单里挑：
  1. 展开后是否保留当前上下文？保留 → 就地展开或锚定浮层；脱离且须专注 → 模态或独立页。
  2. 临时查看还是持续使用？临时 → 易关闭的浮层；持续 → 留在内容流（折叠区、分段切换、侧栏）。
  3. 是否含输入或选择？纯解释 → 最轻量的提示；含交互 → 可聚焦、可键盘操作的载体。
  4. 互斥还是并列？互斥 → 同一时间只显示一个分支；并列 → 分组后折叠次要组。
- **常见组合**：保留上下文 + 临时 + 含交互 → Popover、DropdownMenu；保留上下文 + 持续 / 互斥 → Tabs、ToggleGroup、Accordion；脱离上下文 + 须专注 → Dialog、Sheet；需要深链或分享 → 独立路由。组合推不出载体时，沿用应用内同类场景的既有处理，一致优先于局部最优。

## 3. 场景判据与收纳禁令

- **表格与列表**：行内仅保留识别与判断所需的列和主操作，次要操作进入尾部溢出菜单，完整详情进抽屉或详情页。
- **专业工具与设置**：常用高频项一次点击可达，危险设置单独成区直接可见，不藏进折叠区。
- **越界禁令**：
  - **不为收而收**：仅有一两个次要操作时直接呈现，不做溢出菜单；收纳后入口比原内容更难理解时不收。
  - **关键信息禁止仅悬停可见**：后果、禁用原因、报错不得只放在 Tooltip 中；触屏悬停不可达。
  - **禁止浮层嵌套浮层**：模态内不嵌套模态；二级内容改为模态内分步或锚定浮层。
  - **入口必须显式可识别**：收纳入口使用带可访问名称的图标或带状态标签，禁止依赖用户猜测隐藏手势。
  - **展开不推翻前提**：展开后出现的补充内容不得推翻用户基于收起态已做出的判断。

## 验收清单

- [ ] **眯眼测试**：模糊细节后，首要焦点、分组与阅读路径仍然清楚，视区无等权区块混战。
- [ ] **逐项可答**：首屏每个可见元素都能说出用户此刻用它做什么判断或操作；答不出的元素移除或收纳。
- [ ] **移除测试**：逐项移除卡片、边框、背景、图标、颜色与动效；不损失含义或可供性的元素不恢复。
- [ ] **同级测试**：每组重复结构的对象具有相同语义、结构和操作；不等价对象已通过排序、分组、占比或密度体现差异；数据图表真实对应数值。
- [ ] **移植测试**：只替换文案后，主要组织方式不能直接套用于无关业务；能套用说明构图由模板主导，须按内容重做。
- [ ] **收纳可达**：首屏关键信息无折叠；收纳入口显式可见，无仅悬停可见的阻断性信息；同类内容的收纳方式在应用内一致。
- [ ] **两态受检**：收起态与展开态均经过检查，浮层未嵌套浮层。
- [ ] **响应式测试**：窄屏通过重排保持层级与操作，不靠截断关键内容或缩小正文维持桌面构图。
