# 信息呈现与文案

界面上的信息和文案，核心是帮用户做决定和完成操作。字不在多，而在管用。

## 信息取舍（别堆废话）

- **有用才留**：放一个字段或一句话之前，先问一句：“用户缺了这条，会不知道怎么操作还是会选错？”答不上来就直接删掉，不留正确的废话。
- **别按数据库直接平铺**：核心业务数据（如状态、金额）在主视区直接展示；偶尔才查的字段（如对账明细、发票、审计记录）收进详情抽屉或二级页。
- **不解释内部实现**：直接讲业务结果，不向用户解释底层表结构、数据同步机制或接口权限判断逻辑。

## 关键代价与限制（操作前讲清）

- **操作前告知代价**：扣钱、消耗配额、不可撤销的破坏性操作（如删除、清空），在点击前明确展示，不在提交报错后才告知。
- **禁用原因就近提示**：按钮或控件置灰时，就近说明“缺什么条件”（如“请先绑定支付方式”），不让用户猜。
- **重要条件不上浮层**：必填项、关键限制与阻断原因必须直接在页面显示，Tooltip 只用来解释专有名词或做辅助说明。

## 文案与反馈（给原因、给落点）

- **报错与异常给因果**：禁止只甩一个“失败”或“异常”的孤立标签；讲清具体原因和接下来该怎么做。原因未知就如实说明，不编造诊断。
- **操作后交代落点**：明确操作后的预期——是立即生效、进入排队还是需要审批？大约要等多久？谁会收到通知？
- **空状态给引导**：不留白板，也不只写一句“暂无数据”；说明为什么是空的，有后续操作时提供直接的行动按钮（CTA）。
- **指标对比讲严谨**：数值对比时交代时间段和基准；分清百分比和百分点（如转化率从 1% 涨到 2% 是增加了 1 个百分点，相对增幅为 100%）。

## 怎么呈现（直接露还是收起来）

| 场景 | 处理方式 |
| --- | --- |
| 影响风险判断、必须核对或跨项对比的信息 | 直接在主视区展示，配合对齐和排版支持扫视 |
| 仅用于后续追溯、深入排查或审计的细节 | 放进详情抽屉、折叠面板或二级页面 |
| 术语定义、计算口径等辅助解释 | 使用 Tooltip 就近展示 |

## 快速自查

- 删掉这句说明或这个字段，用户操作会卡住或做错决定吗？不会就删掉。
- 关键限制、扣费代价和禁用原因，用户在点按钮前能一眼看到吗？
- 报错和空状态，告诉用户接下来该干什么了吗？
